# Third-Party Dependencies and References

Every external project is recorded here. "Reference only" means we studied its
architecture and did **not** incorporate its code. The full transitive dependency set, with versions and licences, is
machine-generated by standard tooling and checked in:
[`security/sbom.cdx.json`](security/sbom.cdx.json) (Python, via **cyclonedx-py**)
and [`security/sbom-sidecar.cdx.json`](security/sbom-sidecar.cdx.json) (the Go
sidecar, via **cyclonedx-gomod**). `backend/scripts/gen_sbom.py` regenerates
both and runs the vulnerability scans. This file is the human-curated summary
of the *direct* dependencies and the decisions attached to them.

> **History:** earlier revisions of this file described a Go-everything design
> (golang-jwt, MicahParks/keyfunc, vitess sqlparser). That was superseded by
> ADR-0006 (Python backend) and ADR-0007 (Coraza sidecar). The table below
> reflects the code that actually ships. Phase 12 regenerated it against
> `importlib.metadata` and `go.sum`, not memory.

## Vulnerability scanning

`gen_sbom.py` runs, and the last run reported:

| ecosystem | tool | result |
|---|---|---|
| Python | **pip-audit** (PyPI advisory DB) | 101 packages, **0 known vulnerabilities** |
| Go | **govulncheck** (call-graph aware) | sidecar module, **0 reachable vulnerabilities** |

govulncheck is call-graph aware: it reports a CVE only when the vulnerable code
is actually reachable from the sidecar, not merely present in the module graph.

## Re-check policy

Licences and vulnerabilities are re-checked at every dependency bump.
`gen_sbom.py` regenerates both SBOMs and runs both scanners; it exits non-zero
on any known vulnerability or any unresolved row here. A scan whose tool is
absent is reported **UNVERIFIED**, never silently passed. A release build must
additionally lock the Python ranges — there is no `uv.lock` in-tree yet.
